## Decisions taken

1. **Compare inputs, not a dirty flag.** seedr.c does not tell the preview when to render; the preview sees every
   input change itself, so recorded trigs and other tracks' changes are covered without hooks in seedr.c.
2. **The strip shows the recipe as it stands**: the seed in the title bar. After YES the strip equals the track; a
   YES with no knob turned takes the next seed, and the strip shows it after that YES. The alternative, showing
   seed + 1 when no knob was turned since the last YES, would show what the next YES writes, but would disagree with
   the title bar. **For the lead to confirm.**
3. **When YES would write nothing, the strip says why**, in the words YES uses, for as long as it holds (FX track,
   Euclid on, a layer not built).
4. **No lock-row check in the preview.** NO LOCK ROWS LEFT appears at YES only. `dev->room` takes a temporary
   6 KB snapshot when there is no audition, and during an audition compares against the take's rows, not the
   original's. See requests.
5. **VIEW shows the track as it is** (during an audition: the take), not the preview.
6. **The small trig box in VIEW is 4 × 5 px** (0.3: 2 × 3), so a muted trig can be drawn hollow.

## Cost (the emulator; `build/emu/30-preview/cost.txt`)

dtboot counts the instructions the CPU executes; the rest of a run's budget is idle and skipped. Cost of a render =
(instructions executed in a run of 16 DENS turns, each a new value and one render) − (the same run with DENS held
at 0: no change, no render), divided by the renders. Times are at the emulator's 200 M instructions a second, not
measured on a unit.

| Case | Instructions a render | Time at 200 M/s |
|---|---|---|
| 64 steps, RANDOM with BIAS, ROT, SKIP, VEL range, SHAPE NOT 1, ACC, HUM, NOTE range, both lanes 50 %, COND, RTRG, RAND | 194,467 | 0.97 ms |
| 16 steps, RANDOM only | 22,476 | 0.11 ms |

A render happens at most once per drawn frame (preview.c), so a fast turn that moves several values between two frames renders once.

Idle (no render), 1 s on RHYTHM, from a separate experiment with a build in which `pv_draw` returned at once (the
switch was not committed):

| | Instructions executed in 1 s |
|---|---|
| seedr open, 16-step track / 64-step track | 528,229,795 / 528,893,360 |
| the same, `pv_draw` off | 525,972,955 / 525,973,462 |
| VIEW | 525,954,350 |
| seedr closed (stock's TRIG page) | 510,363,412 |

The preview's compare and strip cost 2.3 M instructions a second on a 16-step track and 2.9 M on a 64-step track
(1.1 % and 1.5 % of 200 M). The rest of seedr's screen costs 15.6 M a second (7.8 %), on every page, VIEW included;
that is not F10's code (title, cells, `dev->read` every draw) and is a candidate for M2's performance task.

Sizes: `.run` 48,653 bytes, `.bss` 103,120 (0.4: 46,317 and 96,404). The `.bss` growth is the preview's render
buffers (`struct seed_work`, `pv_out`, the last inputs).

## Open points

- **Lane values in the preview after a PARM change during an audition.** The original was read for the lane
  parameters at the last YES; if LOCK PARM changes while auditioning, `pv_out`'s lane values are for the old
  parameter until the next YES. The strip does not draw lanes, so the screen is right; only `pv_out` differs.
- **Found while drawing VIEW:** trigs that seedr writes have the flag word 0x0001 / 0x0011, without the SYN / SMP /
  ENV bits (0x0080 / 0x0100 / 0x0200) that a trig placed with the TRIG keys has (0x0381; `firmware-notes-os174.md`).
  VIEW draws them as the small box. Whether such a trig plays the synth and sample on the unit is not checked by any
  test here; it is the device layer's (`rt_seed_write_step`, `RT_SET_TRIG`), so it is reported, not changed.
- The top-level screenshots in `docs/screens/` (from 10-pages) now show the preview in place of the track; they
  were not replaced.
