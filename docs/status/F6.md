### The rule

| Term | Meaning |
|---|---|
| list | NLEN (1..16) items; item i is `seed_rand_range(lo, hi)` from slot + 0x100 + i (a P3 slot each), then the items are sorted low to high |
| index | the trig's place among the track's trigs (as the stages count it: every trig, chosen by a lane's % or not) |
| UP, DOWN | place `index mod N`, or N − 1 minus it |
| PING | 0 1 … N−1 N−2 … 1, period 2N − 2 (N = 1: 0) |
| PNG2 | 0 1 … N−1 N−1 … 0, period 2N |
| ODD | the even places 0, 2, 4 …, then the odd ones 1, 3 … (the 1st, 3rd, 5th, then the 2nd, 4th), period N |
| RAND | `seed_rand_range(0, N − 1)` from slot + 0x140 + index |
| LEGATO | g = steps from the trig to the next trig, round the loop at the track's length (a lone trig: the length); the smallest length code whose duration is ≥ g steps (firmware notes, LENGTH) |

## Decisions taken

1. **The list is sorted.** UP and DOWN are then rising and falling lines, as an arpeggiator's, rather than the
   order the items happened to be drawn in (which would make UP and DOWN sound alike).
2. **RAND's picks use slot + 0x140 + index**, inside the LIST block (0x100..0x1ff) that `seed.h` gives the items;
   items use 0x100..0x10f. No other module uses these slots.
3. **Nothing is refused for a list's own knobs.** `seed_value_list` cannot report an error (`seed.h`), and the
   stages are 0.2's: a length outside 1..16 is clamped, an unknown order is UP. The page table keeps the knobs in range.
4. **The index counts every trig on a lane**, not only the locked ones (as `values.c` counts it), so raising %
   keeps each lock's value as well as its step (I4); the host test checks it.
5. **LEGATO rounds up**: a gap with no exact length code (odd gaps above 32 steps) gets the next code up, so the
   note reaches the next trig. Micro timing is ignored. The largest code used is 110 (64 steps); INF is never used.
6. **LEGATO ignores LEN** (as `values.c` already did) and runs on the final positions (after PLACE, P5).

## How to test

```sh
export WORKSPACE=~/dev/github/elektron B=$WORKSPACE/analog-emu/target/release ELEKLOADER_CROSS=m68k-elf-
make -C lib test                # test_values_list among them
make -C lib coldfire

sh tools/run_tests.sh 26        # or everything: sh tools/run_tests.sh
```

Host (`test_values_list`, 46 checks): the items come from their slots and are sorted; UP repeats every N; DOWN,
PING, PNG2 against UP's list for every N 1..16, and by hand for N = 4 and 5 (ODD); RAND picks only items, all of
them over 64 trigs, deterministically; one-value ranges, either order of lo and hi, length 1, lengths and orders
out of range; `seed_value` uses the trig index, not the step; VARY 100 keeps every list, 0 changes it, 50 keeps
40..60 % of the items. LEGATO: every gap 1..64 against the firmware notes' length table (written out again in the
test), known gaps (1/16, 1/8, 1/4, 1/1, 3 steps), the wrap, steps past the length ignored, odd gaps above 32. In
the chain: NOTE and LEN lists (I3: nothing else changes), LIST with DEF leaves the track identical (I1), LEGATO on
TRACK and after ROT and SKIP, a track without lengths left alone, both lanes with exact counts and values, lane %
nesting with values (I4), clamping to the parameter's range, VEL and RATE lists; 2,000 random tracks and recipes
with lists and LEGATO: every render succeeds, is deterministic (I2), changes only note, length and lanes, and stays
in range, steps past the length untouched (I6).

The tests were checked against four deliberate bugs, one at a time (ODD's second half off by one, the list
sorted high to low, LEGATO rounding past an exact length, RAND using one pick for every trig); each makes the
test fail.

Emulator (`26-lists.sh`, 12 checks after the kept2 fixture): NOTE -5..+7 as LIST UP of 4, PING of 5, then LEGATO;
LOCK lane 1 LIST ODD of 3 at 100 %; lane 2 (DOWN, FRQ) LIST RAND of 6 at 60 %, read from the lock store; NO
restores both; YES with no knob turned is seed 3 (V2); kept, SAVE and RELOAD PATTERN keep the take. Each take
compared with seedref.

## Open points

- **Render cost of a list.** `seed_value_list` draws all N items again for each trig (it keeps no state, and its
  signature gives it one index). At VARY 0 that is one hash per item. With VARY near 100 each draw can walk back
  up to 64 takes (`seed_rand`), so NOTE and both lanes as 16-item lists on 64 trigs could take a few million
  instructions a render, against F10's 0.2 M for a full render without lists. Not measured on the emulator. If it
  shows in the preview, the cheap fix is to build the list once per stage: a `seed_list_make` / `seed_list_at` pair
  in `seed.h`, called from `values.c`, `dyn.c` and `trig.c` (a contract change, so the lead's).
- **For Alan**: LIST sorts its values (decision 1); ODD is odd places then even (1 3 5 2 4), the design does not
  say what ODD is; LEGATO rounds up and ignores micro timing (decision 5).
- VEL, CVAL and RATE take LIST in the engine, but no page offers a source for them (V9 leaves room for it).
