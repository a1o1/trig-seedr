## Findings

- **The sequencer plays what seedr writes** (S2's open point): the take's trigs sound on the second CPU's track
  output, on their steps.
- **Saving on the Syntakt**: Save Ptn needs a project saved on the card first (the preset project answers "Prj
  must be re-saved!"); Save Proj is FUNC + GLOBAL (a slot list, then SAVE PROJECT AS with the name; YES saves);
  LOAD PROJECT is GLOBAL, PROJECT, LOAD PROJECT. analog-emu's MENU key is stock's `...` key (the song-mode popup).
- **Power off**: analog-emu still writes no working state on the Syntakt, so 03 checks the card through a project
  load after the cold boot (the cold boot itself comes up on the preset project).
- **Selecting a track**: TRK + a trig key with grid recording off; the FX key selects the FX track.
- No bug was found in the device layer or the mod: every comparison with seedref matched as first written.

## Not tested

- The working state across a power cycle (analog-emu's power-off model is the Rytm's; S0.2's open point).
- Machine-specific lock lanes: a track's machine type is not found (S2, S3), so the lanes are the shared pages.
- ROTATE ALL (no whole-step shift found, S3), retrig (not a field), chord notes beyond being kept.
- The lock-row limit (12 on the Rytm): the Syntakt's lock store has no row pool (S0.4), so there is no limit to
  test; a full step (71 slots) is not reached by two lanes.

## Open points

- 15-play measures one track's onsets; velocities and micro timing are not checked by ear or level.
- 41's sample is the Rytm's (`test_fuzz --sample`): its lane parameters are read as indexes into the Syntakt
  track's list; a Syntakt-specific sample (lanes over the whole list) would cover more parameters.
