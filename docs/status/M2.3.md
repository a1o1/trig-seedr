## Done

- **Measured** (`tools/tests/42-perf.sh`, results in `build/emu/42-perf/perf.txt`): the mod's size and `.bss`, the
  render cost per source and per layer on a 64-step track, the cost of seedr's screen while nothing changes (on
  RHYTHM, TAKE, VIEW, and while playing), and the lock rows a take uses. Tables below, before and after.
- **seedr's screen draws a frame only when it may have changed** (`mods/seedr-ar2/seedr.c`). Until now `gr_tick`
  marked stock's view dirty on every tick (20 Hz), so stock redrew its TRIG page and seedr its whole screen 20 times
  a second with nothing changed. Now a tick marks it only after a key or knob event or a message, while a stock
  overlay is up (as before), or when an input of the screen differs from the last frame drawn in full
  (`struct scr_key`: the current track and pattern, the track's steps and lanes as `dev->read` gives them, the
  pattern's trigs as `dev->context` gives them, Euclidean mode, a message running out, and the settings seedr's own
  events change). A frame stock draws for its own reasons while nothing differs gets a copy of the last one (1 KB).
  The screen shows the same as before; only frames that would repeat the last one are not drawn.
- **The title bar is filled a byte at a time** instead of 1,280 `dot` calls (the same pixels).
- **F6's list speed-up** (`lib/values_list.c`): `seed_value_list` keeps the last list it made and uses it again
  when the range, length, slot and the take's numbers are the same, so a stage makes each list once instead of once
  per trig. A host test (`test_kept` in `lib/test_values_list.c`, 20,000 calls with the inputs varied one at a time
  and in mixes against a list made afresh) checks it; removing any of the key's fields that matter (range, slot,
  salt, VARY) from the comparison makes it fail. QUAL's candidate is in the key as well, though list slots do not
  depend on it (`seed_rng.c` mixes the candidate into RHYTHM and PLACE slots only).
- `tools/tests/42-perf.sh`: 84 checks (each cost run renders once per SEED value and never at a held value; the
  idle screen draws nothing in full and costs below 0.5 % of the CPU and below a fifth of drawing every tick; the
  screen follows a trig recorded with stock's keys on VIEW, another track changed while BD copies it, a message
  running out, playing, each compared with a full redraw; lock rows taken and given back).

### Lock rows

From the `kept2` fixture on pattern A01: 14 of the 72 rows used (none on BD). A take on the 64 steps of BD with both
lanes at 100 % (lane 1 SMP, lane 2 FRQ): 16 used, 2 on BD, one per lane parameter, whatever the number of locked
steps. NO gives both back (14 again). So a take costs at most one row per lane parameter on the track (two for a
fine parameter, `firmware-notes-os174.md`), at most 24 for every voice track with two coarse lanes.

## Decisions taken

1. **Redraw on change, with a complete key rather than a hash.** The key holds copies (the track as read, the
   context, the recipe) and is compared exactly, so an equal key means an equal frame; any doubt (an event, an
   overlay) draws in full. A frame drawn in full also stores the settings the draw itself changed (a page skipped,
   a lane reset, a new recipe), so the cached frame never stands for a state the draw would change.
2. **Every key event sets the dirty flag**, including keys seedr passes to stock (TRIG keys, PAGE), so stock's
   changes to the track are drawn at once without relying on the read alone.
3. **The list cache compares field by field**, not the `struct seed_take` bytes (a stack copy's padding is not
   defined), and includes the candidate although list slots do not use it.
4. **The render-cost method** now draws one frame per turn in both runs; the bias of the preview's compare is
   stated and corrected in the source table, not hidden. `scr_always` is kept as a test poke so the old behaviour
   can be measured in the same build.
5. Not changed: the preview's compare (byte by byte, about 6,400 instructions, now only on frames drawn in full),
   the cells' text drawing, the device layer (`device/rytm_ar2.h` is the lead's).
