## Decisions taken

1. **CHAOS's scale is the original's**: the offset is `byte × (CHAOS >> 2) >> 8`, so CHAOS 255 lifts a level by at
   most 62, and CHAOS 1..3 do nothing. The design says only "a chaos offset"; keeping the original's scale is what
   makes the trigs match it.
2. **The overflow rule is the original's**: a level that would pass 255 becomes 255.
3. **Levels are exactly `ReadDrumMap`'s**, including the 8-bit mix's rounding down: on a node itself (X = Y = 0) a
   level of 255 reads 254. The comparison is bit-exact, so nothing was "improved".
4. **The places (`drum_map`) are in `map_data.c` too**, as they also come from the GPL-3.0-or-later sources. Both
   arrays are declared `extern` in `src_map.c` and in no header: `seed.h` is frozen and nothing else needs them.
5. **The chaos slot's index is part × 256 + pass** (as `seed.h` says), so changing PART changes the lift, and each
   32-step pass of a 64-step track has its own (the original draws a new one at each pattern start).
6. **PART outside 0..2 refuses** (`SEED_E_ARG`, as RANDOM does for ROLE); DENS, X, Y and CHAOS are clamped to 0..255.
7. **`23-map.cc` is GPL-3.0-or-later**: it compiles the original files in. It is a test tool, never part of a mod
   build. `test_src_map.c` holds hashes, not levels, and stays GPL-2.0-or-later.
8. **Names** (hard rule 4): no "Mutable Instruments" or "Grids" in the page rows, `docs/v1/map.md` or `mod.json`.
   They appear in the README's acknowledgements, and as source paths (`grids/resources.cc`) in the provenance notes
   of `map_data.c`, `23-map.cc`, `23-map.sh` and the code comments that say which original function is followed.

## How to test

```sh
export WORKSPACE=~/dev/github/elektron B=$WORKSPACE/analog-emu/target/release ELEKLOADER_CROSS=m68k-elf-
make -C lib test               # test_src_map among them
make -C lib coldfire
sh tools/run_tests.sh 23       # the original-code comparison, then the emulator, about 6.5 minutes
sh tools/run_tests.sh          # everything
sh tools/golden.sh
```

`23-map` needs the workspace's `mi/eurorack/grids/` (`resources.cc`, `pattern_generator.cc`) and a host C++
compiler (Apple clang's `c++`); it stops with a FAIL when the original files are missing.

## Open points

- **ACC with AMOD = TOP does not reproduce the original's accents.** Design section 6 says it does, approximately,
  but `seed_acc_top` (F1) ranks trigs by Barlow's metre, not by map level. `docs/v1/map.md` says the accents are not
  written and that SHAPE = MAP makes those steps loudest. Matching the design would need the level as the rank
  (an AMOD = MAP, or TOP using the map level when SRC = MAP), which is a contract and F1 change. For the lead.
- **The title bar shows S and the seed with MAP** even at CHAOS below 4, where the seed does not change the rhythm
  (as F2 noted for EUCLID). For the lead or F10.
- **`props.h`'s random recipes draw only RANDOM as a source**, so `test_props.c` does not cover MAP;
  `test_src_map.c` runs the same checks with MAP forced (as F2 did for EUCLID).
- **A1 in the emulator** is checked by where X and Y land (`shared`, not BD's recipe); the emulator test does not
  switch tracks. The host test checks that tracks share them.
