### The original's rule

`EvaluateDrums` (`grids/pattern_generator.cc`): for each part, `level = ReadDrumMap(step, part, x, y)`, plus the
part's perturbation for the pattern (`U8U8MulShift8(random byte, randomness >> 2)`), clipped to 255; the step fires
when `level > ~density`, and a step that fires is accented when that same `level > 192`. The accent is decided on
the perturbed level, so with CHAOS the lift counts; that is why TOP needs the lift as well as the level.

Within a take the trigs whose key is above 192 are always a top set by key (the key decides both), so some ACC %
selects exactly them. ACC is a percentage of the trigs: with at most 64 trigs every count 0..n is `round(p × n / 100)`
for some p, so a matching ACC exists for every take (the tests check this, not only assume it).

## Contract change (for the lead)

One prototype in `lib/seed.h`, after `seed_map_level`:

```c
/* src_map.c (F3, F12): the part's chaos lift for the pass of 32 steps holding step, 0..62 (CHAOS
 * 0..255), or SEED_E_ARG; a step's key is its level plus the lift, at most 255 */
int seed_map_lift(const struct seed_take *k, int part, int step, int chaos);
```

`seed_map_level` alone gives the level, but the original accents on the level plus the chaos lift. Without the lift,
TOP matches the original only with CHAOS below 4, or within one 32-step pass (the lift is the same for every step of
a pass, so it does not change the order there; it does across the two passes of a 64-step track, and it decides which
trigs pass 192). The alternative to a prototype was to copy the lift's draw into `dyn_rank.c`; that would keep two
copies of F3's rule that must stay equal. The mutation check below shows the test catches a key without the lift.

`seed_map_lift` takes a step, not a pass number, so `dyn_rank.c` does not need to know the map is 32 steps long. It
costs one `seed_rand` per step in `seed_acc_top` (only with SRC = MAP, ACC > 0 and AMOD = TOP).

## Decisions taken

1. **The key is the source's key**: level plus the part's chaos lift, clipped to 255 — the value the trig fired on
   and the original compares with 192. The lift is read from the RHYTHM slot (`SEED_P_CHAOS`) at the same take; no
   DYNAMICS stream is drawn, so TOP stays seed-free apart from what the trigs themselves depend on.
2. **Final positions** (P5): the key is read at the trig's position after PLACE, as SHAPE = MAP reads its level. A
   generated step has no origin to look back to, and accents that followed the trig through ROT or SYNC would differ
   from SHAPE = MAP's velocities. With PLACE at 0 the positions are the source's, which is the case the original
   defines. `test_rot` checks this.
3. **Ties to the earlier step**, as F1's TOP (`seed_keys`). Ties only matter inside one key value, so they never split
   the original's accents from the plain trigs.
4. **TOP on MAP ignores METR and BEAT**; on every other source it ignores the MAP settings (`test_sources`).
   `dyn.c` still refuses TOP with a meter out of range before writing, also on MAP (F1's check; the knobs cannot
   reach such a meter).
5. **I3**: accents now follow PART, X, Y and CHAOS with SRC = MAP. These are RHYTHM settings (X, Y, CHAOS the
   pattern's), and props.h's I3 already exempts RHYTHM changes; SHAPE = MAP's velocity has the same dependency.
6. **No new knob or AMOD value**: TOP's meaning follows the source, as the task asked. The ACC share that matches
   the original is not set automatically; the docs explain how to find it.

## Tests

**Host** (`lib/test_dyn_rank.c`, 147 checks; no access to `mi/`): the original's rule over 6 × 6 X / Y, 3 parts, 8
DENS, 5 CHAOS and lengths 16, 32, 37, 64 (17,280 takes, with every case kind: some, none and all trigs accented),
with the key written out in the test (level from `seed_map_level`, which `23-map` checks against the original, and the
lift computed from `seed_rand` directly); for every ACC 1..100 the accents nest (I4), their count is the share (I5)
and only trigs carry them; no accented trig has a lower key than a plain one, ties to the earlier step (with clipped
keys); after ROT the key is read at the final position; with TRACK, RANDOM and EUCLID TOP still picks the 4/4 beats
and ignores the MAP settings; with MAP it ignores METR; ACC changes only the accent flag; `seed_map_lift`'s
arguments, bound (62) and CHAOS below 4.

Mutation check (by hand, `dyn_rank.c` restored after): ranking by the meter under MAP fails 4 checks; a key without
the lift fails 2.

**Against the original code** (`32-map-accents.sh` section 1, `32-map-accents.cc`): `pattern_generator.cc`'s accent
rule is still `level > 192` after `level > threshold` in `EvaluateDrums` (an awk check on the source); then
`seed_render` with SRC = MAP, AMOD = TOP and ACC at the matching share against the original's rule with the original
`ReadDrumMap` and `resources.cc`, for 6 × 6 X / Y, 3 parts, every DENS 0..255, 5 CHAOS, 16 / 32 / 64 steps, VARY 0
and 60: 829,440 takes, 30,965,760 steps, 0 differ, every take has a matching ACC.

**Emulator** (`32-map-accents.sh` section 2, A01 BD on a new project): SRC = MAP, DENS 200, X 60, Y 190 with the
knobs; ACC at the share `mapacc` gives (30 %), AMOD = TOP; YES against seedref, and the accent flags against the
original's; CHAOS 255 (ACC 50 %), the same two checks; SRC = RAND with TOP against seedref (the meter); NO; MAP
again, YES, FUNC + YES kept.
