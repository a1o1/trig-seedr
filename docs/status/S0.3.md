# S0.3: Synfact's core on the Mac, and elekloader builds in analog-emu

State: ready for review
Branch: worktree-s0-3-synfact (from worktree-s0-2-emu-st)

## Done

- **`tools/st_build.sh NAME [--core st|mini] [MODDIR...]`**: Synfact's elekloader (`../external/synfact-dev`,
  commit `9db6680`, copied to `build/emu-st/synfact` so nothing is written into `external/`) builds the core and the
  mods with the Mac's m68k-elf-gcc 16.2 and patches the stock 1.42 file into `build/emu-st/NAME-emu.syx` with its
  `.syx.map.json`. `--core mini` (the default) is core-st's hook bus alone, generated from the copy: `core.s` and
  `settings.s` at core-st's boot, tick, draw, key, encoder and SETTINGS sites. **Emulator only** (below).
- **`mods/hello-st/`**: a measurement mod. It counts ev_tick, ev_draw, ev_key and ev_enc into one symbol (`hello`)
  and, on its first tick, takes seedr's buffers' size from the native heap and searches the largest block.
- **`tools/st_s03.sh`**: 8 PASS, 1 OPEN, about 100 s:
  - the hook-bus core alone boots to the same main screen as stock (the screens compared as text);
  - with hello: its first tick ran, tick and draw run, the screen is still stock's, the heap gives 107,336 bytes
    (both ends written and read back), TRIG reaches ev_key (press and release) and stock still shows its Trig
    Parameters page, a knob turn reaches ev_enc;
  - core-st: OPEN, it does not link (below).
- **analog-emu**: it chose a profile by the main OS's hash only, so it refused every modified Syntakt image. The local
  branch **`syntakt-modified`** (worktree `~/dev/github/elektron/analog-emu-st`, not pushed, analog-emu's `main`
  untouched) adds a table of 16 stock bytes at each of the 16 code addresses the Syntakt 1.42 profile uses, as the
  Rytm and A4 profiles have: an image that keeps them is "Syntakt OS 1.42 (modified)". `tools/st_s03.sh` uses that
  build (`ST_B` overrides its folder).

## Findings

| | Measured |
|---|---|
| core-st 2.0.3 with gcc 16.2 | `.run` 67,978, `.bss` 1,060 bytes; **refused: RAM to `0x46010e60`, 3,680 bytes past the 64 KiB area** (`0x46000000`–`0x46010000`, the Syntakt profile's only area). Synfact's own builds (gcc 13.2) report 420 to 1,220 bytes free. About 59 KB of it is C, built with the profile's fixed `-O3`; this elekloader's `build()` takes no extra cflags |
| The 64 KiB area | Shared by the core and every ordinary mod. With core-st in it, nothing else fits; seedr's code alone is 57,685 bytes |
| Hook-bus core | `.run` 440, `.bss` 16 bytes: 65,060 bytes of the area spare (64,744 with hello) |
| Native heap (`fw_malloc` `0x401036d0`, `fw_free` `0x401038d6`, task context) | At the first ev_tick, 107,336 bytes at `0x446848c0`; with that held, the largest block is **8 MiB** (8,388,608: every request above 8 MiB fails, a power-of-two allocator); Synfact gives the arena as 16 MiB |
| Container | elekloader's packer ends the main OS at flash `0x292d60`; the profile's limit is `0x26f750` (the official container), **144,912 bytes over**. Synfact repacks with `elektron-firmware-tool` for a unit, and records that a larger file failed a 1.41 transfer. `tools/st_build.sh` lifts the limit in-process: its files are for analog-emu only |
| How a mod depends on a core | `"requires": ["core"]` in `mod.json`; events by `"subscribe"` (`ev_tick`, `ev_draw`, `ev_key`, `ev_enc`, `ev_settings`) with the handler forms core-st documents. No `resources` needed for UI events |
| Builds outside Synfact's tree | `python -m elekloader.sdk.build MODDIR --out DIR` works on any folder; Synfact's own builders write `out/` next to the sources, hence the copy |
| The sample buffer (Synfact's finding, not measured here) | Stock 1.42 builds its sample aggregate from `0x4584f2c5`; past about 84 s of samples it reaches `0x46000000`. core-st 2.0.1 and later stream samples instead, which is what makes the area safe with core-st |

## SD2: recommendation

seedr cannot be an ordinary mod beside Synfact's core-st: the core fills the 64 KiB area by itself. Two ways work:

1. **For the emulator milestone: the hook-bus core and seedr in the 64 KiB area, seedr's large buffers (snapshot,
   take, work: about 100 KB) from `fw_malloc` at the first tick.** 65,060 − 57,685 leaves about 7.3 KB for seedr's
   remaining `.bss`; the heap gives 8 MiB. Testable today with `tools/st_build.sh`. Not for a unit as it stands:
   without core-st's streaming, stock's sample aggregate can reach `0x46000000` (over 84 s of samples). Before a unit,
   either move the area to one proven unused (a canary run, as elekloader did for the A4: the candidate is above the
   full aggregate's end, `0x4759b3c5`, and below the stack at `0x48000000`), or take option 2.
2. **For Synfact users: seedr as an SMZ4 bank module under core-st**: up to 2 MiB on the heap, the same event forms,
   relocatable code (`-fno-jump-tables`). Needs core-st to link (gcc 13.2, or Synfact trimming it) and a way to put a
   bank on the card's `/mods` in analog-emu.

Recommendation: SD1 becomes **our own hook-bus core** (the 440 bytes above, from Synfact's GPL-2.0-or-later sources)
for the milestone, with SD2 = option 1; option 2 stays the route to sit beside Synfact once both run.

## Open points

- core-st does not link with gcc 16.2 (3,680 bytes over): gcc 13.2 on the Mac, or ask Synfact.
- A unit build needs `elektron-firmware-tool`'s repack (not installed) and a safe area (above).
- The analog-emu change (`syntakt-modified`) is local; it belongs upstream in analog-emu.
- Power off in analog-emu on the Syntakt (S0.2's open point) is unchanged.
