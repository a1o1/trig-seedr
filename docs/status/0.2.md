## Decisions taken

1. **An active share knob owns its field on every trig**: ACC sets or clears the accent flag, COND writes a
   condition or none, RTRG sets or clears the retrig flag (the others keep their rate and curve). A lane above 0 %
   is cleared on every step and the chosen trigs get a value, as 0.3's SMP%. This gives exact counts and
   nesting (I4).
2. **VEL = DEF with a shape**: the shape runs from half the trig's own velocity (or the track's default) to that
   velocity. VEL = DEF with only ACC leaves velocity untouched.
3. **HUM 100 = ±32** velocity, drawn per step.
4. **Shape levels**: 0.3's five levels map to 0, 63, 127, 191, 255; the target is `lo + (hi − lo) × level / 255`
   rounded, so it can differ from 0.3's by 1 when `hi − lo` is not a multiple of 4.
5. **EVRY**: every N-th trig counting from the first trig, at the top of VEL; the rest at the bottom.
6. **SKIP clears a step as a generating source does** (`seed_step_clear`): no trig, default fields, no origin,
   swing, unknown flags and lanes kept.
7. **Until F1, the rank is 0.3's weight** (0..4 scaled to 0..65535), used only when BIAS ≠ 0, and only for ROLE
   = METER in 4/4. `src_random.c` uses `seed_rank` as soon as it returns a value.
8. **One RAND knob** replaces GEN's UTIM and GROOVE's RANDOM. It adds up to ±RAND % of the device's range
   (`utime_hi`; 23 on the Rytm) to the trig's micro timing: on a generated step that is GEN's UTIM, on SOURCE = TRACK
   it adds to what is there. 0.3's GROOVE RANDOM 100 (±12) is now about RAND 50. `SEED_P_GROOVE` is unused.
9. **DEF in a value range**: CVAL = DEF is 50 %..100 % (the recipe's default), RATE = DEF is a new trig's rate,
   a lane's DEF is its parameter's whole range. Lane values are clamped to the parameter's range.
10. **A field the track lacks** (`seed_track.fields`) is left as it is; the stage does not refuse (V8: the mod
    hides the knob).
11. **`groove.c` and `groove.h` are unchanged.** `timing.c` applies a `struct seed_groove` itself, and
    `test_port.c` shows it gives 0.3's results. So `groove.c`, `groove.h` and `test_groove.c` can retire with
    `gen.c` at G0, once the mod and `tools/groove2h.py` use `struct seed_groove` (same layout). This replaces
    "0.2 moves them onto `struct seed_groove`" in `0.1.md`.

## Open points

- **For Alan** (cheap to change before 0.4 freezes golden vectors): decision 2 (VEL = DEF shape range), 3 (HUM
  scale), 8 (RAND replaces GROOVE RANDOM).
- **BIAS is much steeper than in 0.3.** With the design's key formula and five levels, BIAS +60 puts 963 of 1,200
  trigs on beats at DENS 25 (BIAS 0: 290); 0.3 reached 685 only at +100. BIAS −60 puts none there. F1's Barlow
  ranks have 16 levels and will change this; F1's status file should give the response curve.
- **F1**: the five-level shapes (STRONG … NOTBAR) and the BIAS fallback exist only in 4/4. Other meters need
  per-meter weight levels; `seed_weight(step, beat)` has no meter argument, so F1 will either edit `dyn.c` and
  `src_random.c` (with this task's agreement) or ask for a contract change.
- **Environment (elekloader, not this repository):** `mods/core-ar2/scenes.c` does not compile with Homebrew
  gcc 16 ("too many arguments to function": C23 makes `int (*)()` take no arguments). `tools/test_seedr.sh`
  prints BUILD FAILED for the core and goes on with the `core-0.13.elemod` already in `out/` (built 2026-11-15
  09:32). Fix: a prototype in `METHOD`'s `method_t`, or `-std=gnu17` in elekloader's flags on the Mac.

## Requests to the lead

1. **`lib/test_seed_render.c` changed** (the lead's file): `test_not_available` expected every stub to refuse; it
   now expects `SEED_OK` or `SEED_E_NA` from each layer's `seed_have_…` flag, so it stays valid as M1 lands.
2. **New files outside section 4's names**: `lib/tests.h` (helpers for host tests; not named `test_*` because
   `.gitignore` ignores `lib/test_*` except `.c`) and `lib/test_port.c` (remove at G0).
3. **`seed_value` cannot report an error**: NOTE and LOCK values can be negative, so −1 (`SEED_E_NA`) is a valid
   value. The stages check the value source before calling it. Suggest a sentence in `seed.h` saying so, or an
   out parameter, before F6 and F7 fill `seed_value_list` and `seed_value_noise`.
