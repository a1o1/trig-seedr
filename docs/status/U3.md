# U3: a unit-shaped Syntakt file

State: ready for review
Branch: worktree-u3-repack-st (from e6291d3)

**Not for a unit yet.** The file is unit-shaped: it has the official container's size budget and the margin the
bootloader needs. But seedr's code and data still sit in the area at `0x46000000`, which stock's sample buffer
reaches past about 84 s of loaded samples (status/S0.3.md). Nobody flashes it before U1's safe area is in the build
and S6's recovery is practised. The file never leaves `build/`.

## Done

- **elektron-firmware-tool** (Marcel Bierling, MIT; `../external/elektron-firmware-tool` at `a5bce9a`, cloned with
  Alan's approval on 2026-11-19). The lead read it before it ran: C11 and the standard library only, with no
  network, no process spawning and no USB or MIDI (`transport.c` is the SysEx framing). `tools/eft.sh` compiles it
  into `build/eft/` when it is missing or the clone's commit changes; the clone is never written to. `-r` rebuilds
  the stock Syntakt 1.42 file byte for byte.
- **`tools/st_build.sh --unit`** (a separate step after the emulator build, which is unchanged):
  - takes the patched MAIN that elekloader linked (section 3 of `NAME-emu.syx`, decoded);
  - rebuilds the stock file with it: `elektron-firmware-tool -i STOCK -c 3 MAIN -l LEVEL`;
  - checks the result with elekloader's `syx.verify` against the Syntakt profile as shipped. That covers: every
    message, the content checksum, every section but MAIN stored and depacked as stock's, the header, the container
    within `flash_limit`, and MAIN depacking in place to the patched image. It also requires an in-place margin of
    at least 4096 bytes (Synfact's rule, `elekloader/sdk/syntakt/build.py`);
  - tries packing levels 3, 2, 1, 0 and keeps the first that passes. Writes `NAME-unit.syx` and its facts,
    `NAME-unit.json`.
- **`tools/st_unit.sh`**: the file checked again with the tool's own reading, then run in analog-emu-st. 9 checks:
  - the tool reads it as Syntakt 1.42 with checksums ok;
  - no HMAC trailer, as stock;
  - every section but MAIN decompresses as stock's (sections 1, 2, 4, 5, 6, 7, 8);
  - MAIN decompresses to elekloader's patched image;
  - the container size and the margin;
  - it boots to the main screen;
  - `tools/tests-st` 01 (8/8) and 13 (21/21) pass on the unit file.
- **`ST_UNIT=1`** makes `tools/tests-st/st.sh` build and run the unit file instead of the emulator build (the same
  linked MAIN, so the same symbol map).

## Findings

| | Container (bytes) | MAIN stored | In-place margin |
|---|---|---|---|
| Stock 1.42 | 2,029,392 | 1,442,812 | 96,357 |
| elekloader's packer (the emulator build) | 2,174,304 (144,912 over) | | 219,939 |
| elektron-firmware-tool `-l 3` | 1,980,480 | 1,393,890 | **−6,892**: refused |
| `-l 2` | 1,986,672 | 1,400,087 | **−695**: refused |
| `-l 1` (taken) | 1,998,272 (31,120 spare) | 1,411,695 | 10,912 |
| `-l 0` | 2,022,512 | 1,435,935 | 35,153 |

- **The budget** is the Syntakt profile's `flash_limit`, `0x80000 + 2029392`: the official 1.42 container's size
  (Synfact's `elekloader/devices/syntakt.py`, "the same conservative policy"). seedr's MAIN is 3,496,904 bytes
  decoded (stock 3,442,576).
- **The tightest packing is not safe.** The bootloader stages the packed MAIN at `0x40200000` and depacks it in place
  to `0x40000400`. A denser stream lets the writer overtake input it has not read (a negative margin), and such a
  file would not boot. Levels 3 and 2 do that for seedr; this is why Synfact packs at `-l 1`. The level is chosen by
  the check, not fixed, so a larger build moves to level 0 rather than failing.
- **The Syntakt 1.42 file has no HMAC trailer** (the tool and the profile agree), so there is no seal to check.
- **Only section 3 changes.** The minimal core patches no AUDIO (section 7), so no `-c 7`.

## Open points

- **The memory area (U1).** The unit file must be rebuilt once U1's safe area is in the build; `--unit` needs no
  change for that.
- **The margin shrinks as MAIN grows:** 10,912 bytes at `-l 1` today. `-l 0` gives 35,153 with 6,880 bytes left in the
  container budget.
- Nothing here measures the transfer to a unit (Transfer, the USB receiver). The Digitone II's 2 MiB stall in
  elekloader's DEVICES.md is a reminder that the size limit for the transfer may be other than the flash budget.
