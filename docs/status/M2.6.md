## Decisions and why

1. **The manual's source is the site's content tree, not `docs/`.** Starlight checks its relative links and image
   imports at build time, the pages need no front-matter rewriting, and screenshots import from `src/assets`.
   `docs/` keeps the files that are also read on GitHub by developers and testers (flashing, testing, requirements,
   design, plan); the site copies those in, as before.
2. **One place per text.** Generate and apply, ranges, hidden knobs and the preview are in Concepts only; other
   pages link there. Value lists and noise are explained once, on NOTE; LOCK and DYNAMICS link to it. The status of
   hardware testing is the table in `docs/flashing.md`; the README, Introduction and Beta link to it (the home page's
   one-line version string and the README badge also name the versions; the lead updates them with each release).
3. **The knob reference is generated** (`sync-docs.mjs` collects every table headed `| Knob | Name | Values |
   Default | Shown |` from the page files into `manual/knobs.md`, git-ignored), so each knob's values, default and
   condition are written once, on its page. The build fails if a page loses its knob table.
4. **Keys and messages** is a page of its own: every key, and every message the strip shows with what it means (from
   `seedr.c`).
5. **Beta** is its own section next to Getting started, so a new user meets it before the manual.
6. **The design is not published on the site.** `docs/design-v1.md` names Grids throughout; plan rule 4 keeps that
   name to the acknowledgements. Requirements links to the design on GitHub.
7. **Screenshots only from `tools/screens.sh`.** The manual uses the top-level `docs/screens/*.png` only. The task
   folders (`docs/screens/f2/` …) were made by older builds and are not shown any more; they stay as task records.
8. **The parked choices** (role orders, SYNC runs, list orders, DRFT scale, CVAR AAAB with !PRE, MAP under PHRS,
   SHAPE = MAP's hidden PART, X, Y) are described as they behave, each with one line saying it is as built in 0.7
   and may change after beta feedback, and listed together on What beta means.
9. **Release notes 0.5 and 0.6** linked `docs/v1/*.md`; their links now point to the manual's pages (URLs on the
   site), the text otherwise unchanged.

## For the lead

1. **`mods/seedr-ar2/seedr.c:257-308`: `take()` is `int` and falls off its end on success** (no `return 1;` after
   `core_project_edited();`). `yolo_run()` (`seedr.c:358`, `if (!take())`) relies on its value, so a successful
   roll can be taken for a failure (the recipe put back) depending on what the register holds. Tests pass today.
2. **YOLO after NO** (`seedr.c:343`, `if (tool.roll == yolo_used)`; the lead changed it for 0.7.1: after NO, or with ROLL turned, YES plays the roll shown): YES rolls the next number after NO, unlike the
   pages' M2.5 rule (the same take back), and turning ROLL back to the number just played also moves on. Documented
   as built on TOOLS; worth a decision.
3. **MAP's X, Y, CHAOS are one set for the session** (`seedr.c:153`, `static struct seed_shared shared`), not reset
   when the pattern changes; design §6 and A1 say "shared by the pattern's tracks". The manual says "shared by all
   tracks".
4. **TRIG CVAL with CTYP = MIX** (`lib/trig.c`, `make_cond`): the A:B conditions MIX writes take B from
   `clamp(r->cval.lo, 2, 8)`, the X% range's low end as an index (so B is 8 at the default and 2 only when the low end
   is 1 % or 3 %). Documented as built; probably not intended.
5. **`docs/v1/copy-mask.md` contradicted the code**: it said COPY and MASK read a Euclidean-mode track's stored
   trigs; `device/rytm_ar2.h:612` and `tools/tests/24-copy-mask.sh` (part 6) read the pattern Euclidean mode plays,
   as `release-0.5.md` says. The manual follows the code.
6. **Comments naming retired docs**, in files this task does not own: `mods/seedr-ar2/test_interplay.c:208`
   (`docs/v1/map.md`: now the manual's DYNAMICS page) and `tools/tests/13-apply.sh:2` ("the site's Keys and pages":
   now Concepts, Generate and apply).
7. **Untested requirements**: A7 (a save with a take pending stores the take) and A9 (YES refused on the FX track and
   on a Euclidean-mode track) have no emulator test (`docs/requirements.md`).
8. With each release: the README badges and status paragraph, the home page's version line
   (`site/src/content/docs/index.mdx`), and `docs/flashing.md`'s table and TS version name the hardware passes.
