## Done

- `device/rytm_ar2.h`: `rt_seed_device()` returns the Rytm's `struct seed_dev` (design section 10):
  - **capabilities:** 13 tracks, 64 steps, every field, micro timing −23..+23, two lanes, 26 lockable parameters with
    names and sound indexes; lane 1 defaults to SMP (sample slot), lane 2 to FRQ (filter frequency).
  - **read** any track: fields, flags, origin = index, both lanes as the stored lock's whole part.
  - **write** with origins: step i becomes a copy of the snapshot's step `origin` (flags except swing, which stays
    with the position, every field, the sound lock, all 42 parameter locks through stock's lock set / clear), then
    t's fields and lanes. A lane value equal to the source's whole part keeps the source's fine part. Only steps
    below the track's length that differ are touched; one change notice at the end. Without an audition the write
    takes its own snapshot as the source and drops it afterwards.
  - **room** per lane and per sound index (I8): every index the write would set needs its stored row, or the new rows
    must fit as stock counts them (two sound indexes of one row type count once, a fine parameter costs 2). A lane
    value outside the parameter's range is `SEED_E_ARG`, an origin outside the track `SEED_E_ARG`. `write` calls
    `room` first and writes nothing on refusal.
  - **context:** caps, track, every track's length and stored trigs (the mod fills shared settings and grooves).
  - **snapshot** (one bit per track) / **restore** (byte-identical record and lock store, through stock's lock set /
    clear so the rows follow) / **drop**, **changed**, **current**.
  - 0.3's interface (`rt_read`, `rt_write`, `rt_snap_*`) is kept as it was until G0; `seedr.c` builds unchanged

## Findings in the stock OS 1.74 (for `docs/firmware-notes-os174.md`)

1. **The flag routine resets a trigless step.** `0x400c2482 (track, step, mask, on)` ORs or clears any mask. Then,
   whenever the step is left without the note trig (bit 0), it calls `0x400c0b18` (note, velocity, length to the
   default, micro timing 0, retrig 46 / 9 / 0), `0x400c0624` (every parameter lock of the step, through the pool's
   `0x400ac86e`) and `0x400c070a` (sound lock to 0xFF). So a write sets flags first, then fields, then locks.
2. **Sound lock:** set `0x400c0670 (track, step, value <= 128)` (voice tracks only; otherwise it stores 0xFF),
   clear `0x400c070a (track, step)`. Both send the step's change notice.
3. **Lock set / clear** (`0x400c058c` / `0x400c05e2`) do not touch the flag word. Their length check lets
   step == length through (`blt`); the device layer never writes there.
4. **Sound index → parameter, voice tracks** (the parameter records at `0x401bfb2c`, 0x34 bytes, +0x04 the index):
   1..8 LFO (MUL, WAV, MOD, DST, SPD, FAD, SPH, DEP), 9..16 the SYNTH page (per machine; 9 is LEV), 17..24 SAMPLE (TUN,
   FIN, SMP, BR, STA, END, LOP, LEV), 25..32 FILTER (ENV, ATK, DEC, SUS, REL, FRQ, RES, TYP), 33..41 AMP (ATK, HLD, DEC,
   OVR, VOL, PAN, ACC, DEL, REV). Read from the stock OS in a scratch folder; nothing from it is in the repository.
5. **Words 42 and 43 of a step's 88 lock bytes are not locks.** In the emulator a step with three locks holds 0 and 3
   there, an empty step 0 and 0. Stock's lock set / clear keep them: after a move by lock set / clear on
   indexes 0..41 only, all 88 bytes of the moved step equal the original's. The device layer writes 0..41
   (`RT_SOUND_LOCKS`) and never these two.

## Decisions taken

1. **Lane values are the stored value's whole part, 0..127** (the lock store keeps value × 256). The screen
   value of a bipolar or scaled parameter (TUN −24..+24, PAN L64..R63) is not mapped yet.
2. **Parameters left out of the lane list** until their ranges are measured: the SYNTH page (its parameters depend
   on the machine), and the stepped settings LOP, filter TYP, LFO MUL, WAV, MOD and DST. Writing a lock past a
   stepped setting's range is untested on stock.
3. **The FX track:** fields micro timing and condition only, no lanes (its sound indexes are the FX machine's).
   Origins still copy its locks; a lock of an index the track does not hold yet is refused, since the FX row table
   is not mapped.
4. **Lane 2's default is FRQ.** The design names lane 1's default only.
5. **`write` returns `SEED_OK` or < 0**, as the contract's other entries; the count of steps it changed, which 0.3's
   `rt_write` returned for the message, is `rt_seed_written()`.
6. **`restore` keeps the snapshot** (the audition goes on, as 0.3's NO); `drop` forgets it.
7. **The snapshot is the source of origins**, so every take renders from the original (V2) and two writes of the
   same take give the same track.
8. **Storage:** 13 snapshots (85.7 KB `.bss`, the same as 0.3's `snaps[13]`), inside a function so a mod that
   does not call the interface pays nothing.

## How to test

```sh
make -C device test        # test_rytm_ar2: 1,879 checks
make -C device coldfire    # the header with the mod's flags: no undefined symbols, size
# the emulator (one suite at a time until 0.5): on the Mac
export WORKSPACE=~/dev/github/elektron B=~/dev/github/elektron/analog-emu/target/release ELEKLOADER_CROSS=m68k-elf-
sh tools/tests/04-device.sh
```

`04-device.sh` builds core-ar2 (only when its `.elemod` is missing) and a test mod, `devtest`, from
`tools/tests/04-device.c` into `build/dev/`. TEMPO moves BD one step, CHAIN auditions a take, SONG restores, FILL
tries a lock no row can hold. The script makes a step with three FLTR locks by hand, through GRID REC and T1 held.
It then checks the move, SAVE PATTERN plus RELOAD PATTERN, a power cycle (I9), the audition's restore (I7) and the
refusal (I8). All snapshots and card images go in `build/dev/`, not in `analog-emu/`. The test mod keeps each
command's return code after a marker word (`dt_res`), which the script finds with `dtpeek find`. So a check fails
when its key never reached the mod, and FILL must return `SEED_E_ROOM`, not just leave the bytes alone.

| `make -C device coldfire` | text 7,758 bytes, `.bss` 92,530 (the check file's own extra snapshot included), no undefined symbols |

```

PASS move: step 2 is step 1 with its locks, step 1 is empty
PASS move again: step 3 has the locks
PASS RELOAD PATTERN: the saved move, three locks on step 2
PASS power cycle: the same steps and locks
PASS CHAIN: a take (moved 3, sample lock on its trig, accent on step 5)

```

The three locks made by hand are on sound indexes 27 (FLTR DEC), 30 (FRQ) and 31 (RES), as the index map in
"Findings" says. RELOAD PATTERN moved the trig back from step 3 to step 2, so the save stored the moved step and
its locks.

Built with Homebrew's m68k-elf-gcc 16.2.0 on the Mac; not yet with gcc 14.2 in the Linux shell.

## Open points

- **core-ar2 does not build with gcc 16 on the Mac.** `mods/core-ar2/scenes.c:212` and `:215` call a method
  through `int (*)()`. gcc 16 defaults to C23, where that type takes no arguments, so it stops with "too many
  arguments". `tools/test_seedr.sh` rebuilds core every run, and here that build failed (`BUILD FAILED`). Both
  suites used the `core-0.13.elemod` already in elekloader's `out/` (dated 2026-11-15 09:32). This belongs to
  elekloader; not worked around here.
- "Plays" in I9 is not checked; the test covers save, reload and the power cycle.
- The emulator test has run on the Mac's emulator only, not on the Linux build.
- Gate 2 (`tools/run_tests.sh`) and gate 3 (golden vectors) need task 0.5. `04-device.sh` is written to run by
  itself and to sit in `tools/tests/`.
- Measure the lane ranges in the emulator and add the SYNTH page and the stepped settings (decisions 1, 2).
