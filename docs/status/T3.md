## Done

- **The page** (TD1): PG_TURING, the ring's last page after TOOLS, on the Rytm and the Syntakt. Knobs A–D: FLAV
  (DJVU, CRPT, SHFT), LOOP (1..16), AMT, BIAS, the track's own recipe fields (T1). Below them the loop's cells (a
  box when a cell's trig is on, a bar for its value) with the playhead's cell outlined; the strip says LIVE and the
  step, or YES: START. The page is shown only when the device defines `SD_LIVE` (the row flag PR_LIVE, `pg_ctx.live`).
- **A live run (TD2's fast path, L6, L7):** a pending take that keeps changing (`A_LIVE`).
  - YES renders the track's recipe with SOURCE = TURING, PHRS and CVAR off, QUAL 1, and writes it (the offline
    take of the run); the machine is kept (`seed_turing_live_start`).
  - Each tick, every step the playhead has passed since the last tick plays one step of the machine at
    step % LOOP (`seed_turing_live_step`, L13) and is written alone (`sd_write_one`) from one render of the run
    (`seed_render_tur`), so live and offline write the same steps for the same run.
  - FUNC + YES keeps the track as it stands and stops; NO puts the original back; closing seedr, another track or
    pattern, RECORD off: NOT APPLIED, as for any pending take. FX track and Euclidean mode refused as for YES.
  - FLAV, LOOP, AMT, BIAS are read from the recipe every tick, so they turn while it runs.
  - FUNC + UP remembers the cells, FUNC + DOWN brings them back (REMEMBERED, RECALLED, NOTHING REMEMBERED).
  - YES while running: every step written from the cells as they are (RESTARTED), no machine step played.
- **Lib:** `seed_turing_live_start`, `seed_turing_live_step` (src_turing.c), `seed_render_tur` (seed_render.c),
  in lib/seed.h with their contract. Host tests in `test_src_turing` (now 225,650 checks): the start is the
  offline run, rendering the run equals rendering the recipe, a live step changes only its step, the same steps
  replay the same run, a locked loop changes nothing.
- **Devices:** the Rytm's `sd_playhead` / `sd_write_one` are T0a's `rt_playhead` / `rt_seed_write_one`; the

## Decisions (the lead's, by the project's precedent; for on-device testing to confirm)

- **L13: the machine is anchored to the playhead**: a live step plays the cell at step % LOOP, as the Labyrinth's
  write head sits on the step it plays. A DJVU jump plays another cell for that step only.
- **The live recipe** is the track's own with SOURCE = TURING, PHRS and CVAR off and QUAL 1 (the machine is the
  variation); the other layers apply as set, re-read every tick.
- **Counts:** the live run's counts go on from the track's length; past 4095 the take's seed moves on by
  count >> 12, as a step's draws read 12 bits of the count.
- **YES on another page while live** puts the original back first (another kind of take), then generates.
- **The run keeps going on every page** while seedr is open; it stops only by the rules above.
- **A one-step track:** nothing passes, so nothing is written live (the Syntakt's playhead does not move there).

## What on-device testing should look at

- The feel of each flavour and AMT live, and whether 1/16 rewrites at high tempo keep the UI responsive
  (Rytm about 2 ms a step, Syntakt about 0.3 ms: T0a, T0b).
- Several tracks: only the track in view runs live (one machine); is a machine per track wanted?
- Leaving seedr stops the run (TD2's fast path): is a run that keeps going while you play wanted?
- Track speeds other than 1x and pattern changes while live (not measured in the emulator).
- What YES while running should do (now: rewrite every step from the current cells).
