## Decisions taken

1. **Isolation by output folder, not by a lock.** elekloader's build takes an output folder (`build(…, out_dir)`),
   so each checkout builds core-ar2 into its own `build/emu/core/` and nothing is written to
   `elekloader/mods/core-ar2/out`. Locks (a `mkdir` folder with the owner's pid; a dead owner's lock is taken over)
   only guard builds and fixtures inside one checkout. The plan asked for "a lock around the core-ar2 build"; this
   removes the shared folder instead.
2. **core-ar2 gets `-std=gnu17` when the cross compiler is gcc 15 or later**, through `build()`'s `extra` cflags.
   No elekloader file changes. With gcc 14 (Linux) no flag is added. The result differs byte for byte from the
   `core-0.13.elemod` in elekloader's `out/` (built by another compiler); every emulator check passes with it.
3. **The mod's state is read, not timed.** Page, open flag and knob values come from the snapshot by symbol
   (`build/emu/<variant>.syx.map.json`), and struct fields by offsets from the cross compiler (`emu.py layout`). A
   knob is turned until its value is right. Knob turns start 600M instructions into a run: a new `dtboot` treats
   every knob as asleep and sends two wake-up turns, while the mod (its state is in the snapshot) keeps a knob
   awake for 2 s (400M) after its last turn and would take those as steps.
4. **Profiles.** `emu.sh` knows release 0.3's `seedr.c` (`r03`: PAGE cycles VIEW … ROTATE, knobs by name) and the
   version 1 framework (`v1`: LEFT / RIGHT, `recipe[]`, knobs as `LETTER:seedref-key`). The profile is chosen by
   the symbols in the build. `v1` cannot run until task 0.3's pages exist; its symbol names are a request below.
5. **The framework for `test_props.c` is `lib/props.h`.** 0.2 writes `test_props.c` (I1–I6 for its layers) while
   0.5 runs, so the framework is a header both use, and 0.5's own test of it is `test_props_frame.c`.
6. **No golden vectors written yet.** With the 0.1 stubs only the five identity recipes render; freezing those now
   would freeze nothing useful. Missing vectors are reported as "not frozen", stub refusals as "pending". The lead
   runs `sh tools/golden.sh --write` at G0 (V11), after 0.2.
7. **Files outside section 4's list**: `tools/emu.py` (the Python half of `emu.sh`), `tools/golden.sh`,
   `tools/tests/fixtures.sh` (shared states, not a test file: `run_tests.sh` runs only `NN-*.sh`), `lib/props.h`,
   `lib/test_props_frame.c`, `lib/golden/recipes.txt`, `lib/golden/orig-a.txt`, and a section in `tools/README.md`.
8. **The dump format** (`seedref`, `emu.py dump`): one line per field, a value per step below the length; flags as
   the SEED_KNOWN and SWING bits only (the Rytm's state bits 0x0380 are not lib/'s); lane 1 is the sample slot
   (sound index 19). The Rytm's new empty track and `seedref`'s default original are identical in this format
   (checked in `01-generate`).

## Open points

- **core-ar2 does not build with gcc 15 or later** (C23: `int (*)()` means no arguments; `scenes.c` calls
  methods through such pointers with arguments). `tools/test_seedr.sh` does not stop on the failure and links
  whatever `core-0.13.elemod` is already in the shared `out/`, so on the Mac its result depends on a file another
  build left there. The harness adds `-std=gnu17`. The lasting fix is in elekloader (`-std=gnu17` in the Rytm
  toolchain's cflags, or prototypes in `scenes.c`): Alan's repository.
- **`test_seedr.sh` part 7 checks the wrong screens.** It assumes the mod was closed over stock's EUCLIDEAN page;
  stock is on its TRIG sub-page there (read from memory, as `seedr.c`'s `trig_subpage()` does), so the first TRIG
  goes to EUCLIDEAN, and "seedr" passes by comparing two EUCLIDEAN screens. `07-keys` starts with one TRIG and
  checks the open flag and the sub-page at every step; the key behaviour itself is as 0.3 describes.
- **"Re-expressed on the new structure."** Parts 1–8 now run on the new harness and pass against release 0.3's
  mod. Against the version 1 mod they need its pages (0.3), the engine (0.2) and the device layer (0.4): at 0.6
  each check is restated with `v1` page and knob names and compared with `seedref` in place of `genref`. The
  harness side is ready for that (`emu_recipe`, the `v1` knob form, `seedref` = the emulator's dump format), but
  untested against a real v1 build.
- **Grooves in `seedref`.** `struct seed_ctx` takes grooves as `struct seed_groove`; `seedref` passes none yet, so
  TIME GRV recipes cannot be rendered. Once 0.2 moves `groove.c` onto `seed_groove`, `seedref` should load the
  same tables the mod builds with (`grooves-live.h` or `grooves-swing.h`).
- **Lane 2** is not in the dump: its parameter on the Rytm is 0.4's choice. `emu.py dump` reads lane 1 only.
- `analog-emu/` holds 118 snapshots and card images from earlier runs of `test_seedr.sh` and by hand. The harness
  does not use or remove them.
